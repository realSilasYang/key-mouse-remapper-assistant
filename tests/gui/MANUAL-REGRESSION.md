# GUI 人工回归清单

在 100% 和 200% DPI 各执行一次：

- 主窗口首次显示尺寸合理，伪表头与五列对齐；第一列“序号”固定 48px 并居中，
  滚轮使用原生 ListView 滚动。
- 主列表和代码编辑器出现滚动条时，轨道、滑块与箭头均为 Windows 原生深色样式；
  鼠标移到滚动条上显示系统箭头光标，拖动和滚轮操作正常。
- 来源按键等伪表头第一次点击升序、第二次降序、第三次恢复代码块自定义顺序且清除
  箭头；第四次点击重新进入升序。
- “序号”表头第一次点击直接降序，第二次恢复代码块自定义顺序并清除箭头；快速
  连续点击始终按这两个状态循环，不出现冗余的升序状态。
- 工具栏中不再出现上移/下移。把首行拖到中部、末尾，把末行拖到顶部，以及拖回原位；
  插入线位置稳定，放开后第一列序号立即重排为 1、2、3……，脚本代码块顺序同步
  变化，程序下次启动后仍保持。列表超过一屏时把条目停在上、下边缘，列表应连续
  自动滚动并允许拖到当前视口之外。
- 先点击任意伪表头进入临时升序或降序，再拖动一行；拖动开始时恢复自定义顺序，
  最终只保存用户拖动后的顺序，不把临时表头排序写回脚本。
- 缩窄各列，让来源、结果、范围和目的出现截断；悬停被截断单元格能查看完整文字，
  未截断单元格不弹提示，滚动、打开编辑器和开始拖动时旧提示立即消失。
- 来源和目标录制按钮可点击，悬停变色并显示手型光标。
- 开始录制后分别按字母、`Win`、`Alt+Tab`、鼠标按键以及一个已经存在映射的来源键；
  录制区应收到对应输入，而系统菜单、窗口切换、鼠标点击目标和原映射均不得触发。
  完成或取消录制后，脚本原有映射状态应立即恢复；若录制前脚本已挂起则保持挂起。
- 录制前临时建立一个全局滚轮热键，开始再取消录制后该热键仍可触发。
- 按住 `A` 后在其释放前再按 `B`，录制区应实时显示 `A + B`；全部释放后
  应保存为同时按键组合，不得拒绝或静默截断成其中一个键。
- 依次执行 `A` 按下、`B` 按下、`A` 释放、`C` 按下，最后释放其余键；
  结果应按首次出现顺序累计为 `A + B + C`，不得因 `A` 已释放而忽略之后实际按下的 `C`。
- 同时按住多个普通键、左右修饰键和鼠标键，录制区应逐键实时扩展；滚轮
  发生时可与当时仍按住的键组成组合，且只有所有可保持按键释放后才结束。
- 录制字母键时，按钮、实时预览、状态信息和保存后的列表均使用大写字母。
- 键盘录制期间逐个按下左右修饰键时，按钮名称和三行 VK/SC 详情立即更新；尚未
  按下主键前不覆盖上一次已完成的录制，按 `Esc` 可恢复原内容。
- 分别长按字母和数字，按下后应立即预览但录制保持进行；弹起后才提交。再按住
  `LCtrl + RShift + A`，依次弹起 `A`、`RShift`、`LCtrl`，前两次弹起后仍应保持
  录制和输入独占，最后一枚 `LCtrl` 弹起时才完成并恢复原有映射。
- 使用可能漏失最后一枚修饰键 KeyUp 的注入/远程输入重复上项；Windows 异步状态确认
  已释放后，录制必须在校准等待结束时自动完成，不能停在蓝色活动态。
- 录制活动时点击来源或目标按钮，按下和抬起都不得被记录为 `LButton`；该次点击只取消
  当前录制，不能因自绘按钮的延迟命令在取消后又立即开始新录制，下一次独立点击仍可开始。
- 长按鼠标中键或侧键时同样只实时预览，弹起后才完成；滚轮没有弹起事件，仍在一次
  滚动消息结束时立即完成。
- 连续快速执行至少 50 次 `Ctrl+Space -> MButton`，并穿插录制取消、脚本重新加载和退出；
  每次松开后 Windows 异步 `VK_MBUTTON` 状态均为未按下，光标不得停留在中键按住样式。
- 键盘、鼠标键、滚轮、媒体键可录制；按钮只显示 `LShift`、`LCtrl + RShift + A`
  这类 AHK 规范名称。
- 未录制、等待首次按键、取消空录制以及清空后，详情区保持空白；捕获到按键后才按
  “按键名称、虚拟键码、扫描码”逐行显示阅读友好信息，不适用的编码明确显示
  “不适用”；多媒体键的 `CMD` 编号保留在状态信息中。
- 同时按住大量左右修饰键再录制主按键时，按钮和详情区按换行内容自动增高，完整
  文字不截断、不覆盖底部命令区，字号保持不变。
- 分别录制左/右 Shift、左/右 Ctrl、左/右 Alt、左/右 Win，阅读名称、VK、SC 均不同；
  再验证“左侧 Ctrl + 右侧 Shift + A”等组合，保存后只有对应侧别组合触发映射。
- 设计目的输入框与来源、目标录制按钮等高，保留上下左右边距并能完整显示至少两行；
  点击不同字符时 caret 落在对应位置，点击标签、状态栏或窗口空白处后输入框真正
  失焦且 caret 不再闪烁。
- 打开设置依次验证跟随系统/浅色/深色、至少两种已安装字体、简体中文和 English；
  保存并原位热应用后主窗口、伪表头、按钮、托盘、设置窗口和代码编辑器主题一致，脚本
  不应因纯显示设置重新加载。
- 使用 Lucide 的命令按钮保持语义相符的图标和主题色；主工具栏新增、暂停/恢复、删除继续
  使用小助手 Emoji 文本。分别在 100%/200% DPI 和中文/English 下确认图标、文字的
  可见重心与父控件垂直中心一致，文字不截断，也不与相邻按钮重叠。悬停仍应变色并显示
  手型光标。
- 主工具栏六个入口和设置页外链悬停约 500ms 后显示当前主题的提示；提示不抢焦点、不接收
  点击、不越出当前显示器工作区。离开、按下、滚轮、窗口隐藏/失焦、主题切换或销毁时提示
  立即消失。使用 Narrator 或 Accessibility Insights 检查自绘控件均报告为按钮并提供
  “按下”默认操作。
- 保存新增映射后由 managed 运行时原位热应用并生效；重复来源和无修饰左键被拒绝，
  GUI 与 input worker 均不重启。
- 顶部工具栏左侧显示“新增、暂停、删除”，右侧依次显示“设置、帮助信息、捐赠”；
  右侧按钮间距稳定、捐赠贴齐窗口右边缘，托盘菜单仍显示
  “重新加载”。
- 设置窗口逐页检查“通用、录制、事件、关于”：在 100%、150%、200% DPI 下均相对主窗口
  居中并限制在主窗口所在显示器的工作区内，全部控件和底部按钮显示完整；快速切页不闪烁，
  关于页隐藏保存/取消；版本、运行时和两个项目入口完整显示，数值越界时错误提示不截断且
  窗口保持可编辑。
  未选择条目时暂停与删除按钮均灰化且无悬浮反馈；选择条目后分别恢复金棕色和红色。
  设置按钮保持较小规格；缩放窗口后右侧工具组整体移动，内部顺序、间距和右边距不变。
  选择一条映射后点击顶部“暂停”，该行显示“已暂停”，对应 RuleSpec JSON 的 `enabled`
  变为 `false`，`@generated-sha256` 同步重生成，映射块仍全部为注释且不含可执行 AHK；
  managed 运行时原位热应用后该映射不再触发。再次点击“恢复映射”后 `enabled` 变为 `true`，
  摘要再次更新并立即恢复生效。
- 双击、悬停 `F2`、右键操作窗都能打开同一条规则的代码编辑器；右键操作窗显示时
  主列表继续拥有焦点，按键、Windows 系统快捷键和其它程序输入均不被阻塞，选中行
  始终保持圆角背景。
- 编辑器中英文使用 JetBrains Mono，中文使用宋体；`Ctrl+S`、保存、取消、`Esc`
  均可用，未保存关闭会确认。
- 编辑器和事件查看器最小化不连带主窗口；最小化期间各自出现在任务栏，主窗口恢复交互。
  从任务栏还原后直接上级重新禁用并恢复正确 Owner；关闭已最小化的子窗口也不得留下任务栏
  条目或禁用的上级窗口。
- 拖动排序后 ListView、选中行和脚本代码顺序立即同步，窗口不关闭、不重建，连续拖动
  仍然有效。新增、删除、暂停/恢复、代码保存、设置保存和拖动完成后均不重启进程，按
  `Ctrl+Z` 都能撤销最后一次操作，`Ctrl+Shift+Z` 与 `Ctrl+Y` 能重做；managed 规则和
  设置原位热应用。撤销只恢复对应的映射区域快照，入口脚本其他内容不参与规则持久化。
- 普通操作成功时不显示历史结果气泡；只有撤销或重做真正应用并完成必要重载后才显示。
  内容为“已撤销/已重做：具体动作：具体映射”，设置历史列出实际变化的字段；空历史
  不提示。气泡位于主窗口客户区左下角，160ms 从上方下滑淡入、完整停留 3 秒、140ms
  向上淡出，不抢焦点；连续撤销/重做立即替换内容并重新计时，隐藏、最小化或打开下级窗口
  时随即收起。
- 在设计目的输入框和代码编辑器中按 `Ctrl+Z`/`Ctrl+Shift+Z` 只操作文字，
  不触发应用历史；焦点位于列表、按钮和其它非编辑控件时触发应用历史。
- 主窗口 `Esc` 优先取消录制或关闭编辑器，否则隐藏到托盘。
- 首次打开后隐藏到托盘并至少连续恢复三次；再分别连续开关事件查看器、设置、
  帮助信息、使用说明、捐赠和新增/编辑代码窗口至少三次，深色模式下标题栏、客户区、列表
  与滚动条均不得闪白。每次恢复、
  切换深浅主题以及重新加载列表时，窗口背景、伪表头、
  ListView 和输入区不应出现白底、整窗擦除或连续闪烁。连续拖动任意窗口边框调整尺寸时，
  所有控件应跟随边框实时布局，不能看到黑/白中间帧、旧位置残影、整窗背景擦除或
  ListView 闪烁；分别快速来回拖动右边框、下边框和右下角验证。
- 事件查看器只显示时间、类别、事件、来源/规则、结果和详情六列，不显示序号列；事件列
  获得原序号列宽度，ListView 四周没有浅色原生边框。任意列临时排序后持续产生超过缓冲区
  容量的事件，旧行仍应准确淘汰，第三次点击恢复事件原始到达顺序。
- 打开事件查看器并持续快速移动高轮询率鼠标至少两分钟；GUI 与唯一 input worker 的 PID
  均不变化，
  `health` 中观察队列保持在 2048 上限内，管道暂满只增加背压/合并计数，不新增
  `worker_failure`。再关闭事件查看器继续移动，后台观察也不得导致周期性进程重启。
- 执行 `./tests/physical-device-evidence.ps1 -DurationSeconds 60`，在倒计时内分别操作
  两套物理键盘和两套物理鼠标；结果必须记录至少两个具有完整 down/up 的键盘设备、两个
  有实际输入的鼠标设备、零残留按键和零采集错误。热插拔矩阵另加 `-RequireHotplug`，
  并在采集期拔出、重新接入一套复合设备；移除与重新到达/重绑必须属于同一个稳定设备
  ID，启动枚举的到达事件不计入热插拔。生成的 JSON 与验收截图一并保存。仅运行
  `-ListOnly` 只能证明枚举，不能按真实输入或热插拔通过统计。
- 来源按键与映射结果列随各自最长内容独立调整；普通内容完整显示，极端长内容在有限宽度内
  按需求分配并继续支持悬浮查看。“新建映射”标题水平居中，上下各有一条主题分隔线并
  保留均衡留白，列表显示区域和项目行距均明显高于旧版。将列表滚到底后，最后一项底边
  应与列表底边贴合，下面不能留下不足一行的空白；改变窗口高度后重复验证。
- 主列表的“来源按键”“映射结果”“生效范围”伪表头和单元格均居中，
  “设计目的”继续左对齐以便阅读长文本。
- 顶部“新增”“暂停/恢复”“删除”使用与小助手一致的 Emoji 文本，不显示 Lucide；
  “保存映射”“清空”的 Lucide 颜色与“设置”齿轮一致。
- “帮助信息”依次验证使用说明、事件查看器和提交反馈：分流窗口关闭后再打开目标窗口，
  主窗口不能被重复禁用；使用说明可选择复制、不可编辑、失焦后 caret 不闪烁，滚动条跟随
  深浅主题；反馈打开项目 Issues 新建页。捐赠窗口的说明、分隔线、标签、微信和支付宝
  二维码间距与小助手一致，两张二维码可实际扫码，`Esc` 关闭后主窗口不最小化并恢复交互。
- 在代码编辑器有未保存内容时关闭，并在事件查看器导出诊断包：确认框必须跟随当前深浅主题，
  长文本和两枚按钮在中文/English、100%/200% DPI 下完整显示；取消后直接上级恢复交互，确认
  后继续原操作，标题栏关闭和 `Esc` 与取消按钮行为一致。
- 托盘、主窗口、编辑器和发行版 EXE 均显示专属图标。
